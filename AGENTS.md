# shoppablecn Repo Context

## Project Identity

`shoppablecn` is a shadcn/ui component registry for e-commerce UI primitives: ProductCard, QuickOptions, and HotspotImage.

- Live at `shoppablecn.dev`
- Milestone status: M1-M5. M6 is the docs site in the separate `shoppablecn-docs/` repo.

## Repo Structure

```txt
shoppablecn/
  registry/ui/          <- source of truth for all components
    types.ts            <- shared TypeScript types (all public API lives here)
    utils.ts            <- shared utilities (formatPrice)
    product-card.tsx
    quick-options.tsx
    hotspot-image.tsx
    hotspot-pin.tsx
    hotspot-tooltip.tsx
    hotspot-link.tsx
  components/ui/        <- shadcn primitives (button, card, badge, etc.) - DO NOT MODIFY
  app/
    page.tsx            <- public landing page
    layout.tsx          <- root layout with ThemeProvider
    preview/            <- internal QA pages (not public docs)
      page.tsx          <- preview index
      product-card/
      quick-options/
      hotspot-image/
  lib/
    mock-products.ts    <- mock Product data for previews
    mock-scenes.ts      <- mock HotspotImage scene data for previews
  public/
    r/                  <- GENERATED - registry JSON files. Never edit directly.
    mock/               <- mock images used in preview pages
    llms.txt            <- AI-readable API summary (created in M5)
    llms-full.txt       <- AI-readable full source (created in M5)
  registry.json         <- registry manifest
```

## Critical Rules

- `public/r/*.json` files are build artifacts. They are generated by `npm run registry:build`. Never edit them directly. After any change to `registry/ui/` source files, always run `npm run registry:build` to regenerate.
- `components/ui/` contains unmodified shadcn primitives installed via CLI. Do not modify them.
- Preview pages live under `app/preview/**`. They are internal QA pages, not public documentation. They have `robots: { index: false }` metadata.
- `console.log` is only permitted in `app/preview/**` files, and only when flagged with a `// preview-only` comment.

## Two-Repo Workspace

This repo (`shoppablecn/`) and `shoppablecn-docs/` are siblings in `shoppablecn-workspace/`. Changes to public API surface (props, types, exported component names) in this repo require corresponding updates in the docs site. However, in any Codex session scoped to this repo, do not touch `shoppablecn-docs/`. Flag any cross-repo implications in your response instead.

## Code Hygiene

Apply these rules to every file touched:

- No `console.log`, `console.debug`, or `console.warn` outside `app/preview/**`
- No commented-out code
- No TODO, FIXME, XXX, or HACK comments; resolve them or open a GitHub issue
- No unused imports or variables
- JSDoc comments on all public props, types, and exported functions
- Rationale comments ("why") are kept; noise comments ("what") are removed

## Commit Conventions

- Format: `type(scope): description`, for example `fix(product-card): wire isWishlisted to aria-pressed`
- Types: `fix`, `feat`, `types`, `registry`, `preview`, `chore`, `docs`
- One logical change per commit
- No "WIP", "temp", or "update" messages

## Verification

Run after every task. All commands must pass with zero errors and zero warnings.

```bash
npm run build
npm run lint
npx tsc --noEmit
```

If a warning cannot be avoided, add an inline suppression comment explaining why and flag it for Vasilis before suppressing.
